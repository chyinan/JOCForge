# Selected real AXML/CHNA graph identity

`frontend::selected_adm_graph::parse_selected_adm_graph` consumes only caller-supplied AXML and CHNA payload bytes. It performs no file access and never receives WAV/data/PCM bytes. The local receipt binds SHA-256 for both metadata chunks. The copied source receipt confirms its Wash collection read zero PCM bytes; this parser does not independently re-open or validate the WAV container.

For the selected profile, CHNA is exactly a 4-byte count header plus 38 fixed 40-byte entries. Each row retains the one-based track index, `ATU_*` UID, track-format reference, pack-format reference, and reserved byte. The parser resolves each UID through the last-document-node indices for track, stream, channel, and pack formats, requires the UID's direct track/pack refs to match CHNA, and requires exactly one referencing object. Object IDs follow only the selected strict `AO_XXXX` valid-input policy. That is deliberately not an emulation of the native formatter's permissive malformed-string observations.

The graph contains 38 rows in the candidate physical host order: ten DirectSpeakers bed rows and 28 object rows. The single bed-master pack's direct channel references remain in XML order; `channel_format_id` identity then joins them to physical bed rows using the existing `SelectedBedChannelJoin`. The selected speaker suffix route assigns one semantic bed role and ID per row, with the direct LFE at physical host 3. The graph receipt supplies a 28-host complement. Candidate object events are extracted from the actual AXML, admitted against source sample count 13,888,071, then joined by physical host to the actual 580-byte same-source DBMD payload through `parse_selected_dbmd_sections`; the candidate control set retains the parsed DBMD rows alongside control52. This candidate API is not bound to the F01E selected job and is not called by production encode.

Descriptor identity uses `ATU_*` track UIDs, not `AC_*` channel-format IDs. The graph rows bind each UID to its one-based CHNA track index, zero-based physical host, descriptor semantic key, and channel/pack identity. The selected regular source relation excludes physical host 3 and maps the remaining hosts in ascending order to typed `CodecSourceIndex` values 11..47. Separate candidate-only generators now produce the eleven Q15 prefix values and nine normalized bed-role points; neither is installed in a shared 48-source owner or connected to the main selected job.

The graph exposes `track_index_for_uid(&str) -> Option<ChnaTrackIndex>`. This is a pure model lookup; it does not mutate a query string or expose the native output-sentinel protocol. Washed native evidence covers four loads, 152 UID lookups and 152 descriptor stores; tests compare the first-load lookup/descriptor joins against the resulting graph. The actual candidate AXML/CHNA/DBMD bytes and the postcomputed 38-row projection are pinned by their source package hashes. The same candidate source's real DBMD parser result matches all 38 raw flag/packed/enum records, and candidate event/control values match 224 same-package downstream consumer boundary words across eight calls; these boundary words are not an independent event-producer oracle.

Wash R4 provides a distinct primary metadata/control receipt. The metadata-only AXML, CHNA, and DBMD are bound to a path-free selected job projection and source extent N=6,522,906. The local primary producer re-parses those payloads, verifies their hashes against that binding, and recomputes 38 physical-host rows including 28×13 object control words. This R4 material does not change the candidate role of `hanabi.wav` or attach its graph to the selected job. The raw original job XML is not distributed and PCM identity remains `NOT_REHASHED`; no full-WAVE or end-to-end claim follows.

## Remaining boundary

This graph/event/DBMD work does not implement arbitrary CHNA reordering, general malformed/duplicate XML behavior, parser-state reset, source field 0, the complete skip-at-field-4 transition, earlier measurement-side prefix calls, complete 48-source installation, F03/F04 audio installation, or full control38 publication. The separate R4 producer covers only defined metadata/control values; bed control bytes 24..51 are deliberately unproduced, and no callback hold/reset or atomic publication exists. Candidate prefix and bed point generators remain secondary-source value slices. Native malformed object-ID behavior remains separate from the strict selected model policy. These are not whole F01G/F01, an application encode connection, end-to-end encoding, or product acceptance results.
