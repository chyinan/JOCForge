# Selected F01E job configuration and DBMD fields

`frontend::job_configuration::parse_selected_job_configuration` parses the selected F01E job XML, validates a 48 kHz/PCM24 descriptor with 1–256 physical input rows and a positive source length, normalizes one explicit rate from 384, 448, 576, 640, 768, or 1024 kbps, and passes the selected row through the existing production profile resolver. The input row count follows the host-index structural capacity; it does not change the selected runtime audio/control or DDP frame-view dimensions. Input/output paths remain references; the parser does not open files.

The parser rejects DTD/entity declarations before XML parsing. It accepts only an unnamespaced `job_config` root and the specified direct-child paths. Duplicate recognized fields reject. The `adm` and `atmos_mezz` branches both refer to ADM BWF files read by the same RIFF loader; the authored branch remains distinct in normalized configuration identity. No variant-specific media behavior is inferred. The output node must be `output/ec3`. The RIFF reader and `PreparedJobInput` separately require WAVE channel count to equal CHNA physical-track count.

The normalized identity names the authored PCM24/48 kHz profile without embedding a fixed 38-row claim; it stores the actual WAVE channel count as its own input field. Output carrier/layout and frame dimensions remain selected-profile values.

Time fields follow F01E.1 exactly: optional `offset`/`ffoa` default to `auto`; `start`/`end` default to empty and accept only their selected aliases; `time_base` is `file_position`; prepend/append silence use the specified zero forms. Loudness, DRC, downmix and trim values are admitted only for the selected fixed row. Field deviations return local `CONFIG_*` errors; the resulting fixed dimensions are then checked by the existing profile resolver.

Hash-bound vectors cover 11 XML cases: three accepted configurations and eight selected rejections. Tests compare normalized config values, reference precedence, optional defaults, and exact local error categories. The XML fixture is a real selected job-config input from the approved package; it is not a synthetic replacement for an ADM graph, PCM source or codec run.

## DBMD input fields

`frontend::dbmd_sections::parse_selected_dbmd_sections` consumes a caller-supplied DBMD byte slice and parses section framing from offset 4. It checks the selected length-header collision, U16LE section lengths, per-section checksum, duplicate IDs, optional zero terminator/tail, required sections 9/10, section9 length 248, section10 magic, and selected track-table bounds. It returns warm-trim mode, authored mode byte, surround-EX mode, and per-track fields in physical track-index order. The field accessor joins by physical host index, not pack/object ordinal.

The parser is stateless and does not open RIFF files. It does not parse the F01G graph or attach track fields to ADM hosts. The job-XML and DBMD parsers are two F01E input-stage slices; they are not a complete F01E owner or a selected encoder pipeline.

Hash-bound F01E vectors cover 11 XML configurations, four authored modes, six per-track fields and ten DBMD fail-stop inputs. Expected values are checked only after the parsers produce actual results. The local fixture is `tests/fixtures/job_configuration/job-configuration-vectors.json`, pinned to the approved base package and the F01E review binding.

## External `job_config` XML ingress

The additive CLI form is `jocforge encode --job-xml <job.xml>`; append `--preflight-only` to validate references and prepare `PreparedJobInput` without starting Meter or creating output. The normal XML mode resolves either ADM BWF XML input branch (`adm` or `atmos_mezz`) and the EC-3 output reference, reads the referenced input with the existing RIFF loader, then passes the original XML bytes and the actual WAVE descriptor to `parse_selected_job_configuration` and the existing selected-profile pipeline. The input branch remains explicit in normalized configuration identity. The positional form `jocforge encode <input.adm.wav> <output.ec3> [--data-rate ...]` remains available and keeps its 1024 kbps default. XML mode takes its rate from the required `data_rate` element; `--data-rate` is not an XML-mode override.

This ingress is deliberately narrower than the DEE job schema. It accepts the selected ADM BWF input through either authored XML branch, the EC-3 elementary output path, and the currently admitted control row. It rejects unknown nodes and attributes, MP4/DASH packaging, and controls whose selected effect or consumer is not closed. Reading and parsing a field does not mean its audio effect is implemented.
