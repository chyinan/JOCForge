# JOCForge orthogonal composition closure

Verified 2026-09-08 from JOCForge `36532efa2fc47b7bb5bf2a5dbe40beeca5c63620`, ETSI TS 102 366 V1.4.1, ETSI TS 103 420 V1.2.1, the local public OpenJOC validator, and the generated composition matrix.

## Decision

JOCForge now has one pure composition resolver:

```text
CompositionRequest -> CompositionResolver -> JocEncodingPlan | CapabilityClassification
```

The resolver owns profile, container, carriage, EMDF profile, bitrate, block partition, dependent count, LFE ownership, canonical channel maps, final JOC owner, and capacity. Existing `resolve_encoding_plan*` functions remain compatibility wrappers over the same resolver.

The cheap matrix is deliberately a classifier, not a media-encode loop. It contains 140,400 rows across the requested dimensions and is generated by `composition_capability_matrix()` without FFmpeg, OpenJOC, PCM, or filesystem access.

## Normative composition rules

- TS 102 366 E.1.3.1.2 requires dependents to immediately follow their associated I0, use sequential D0..D7 IDs, and use the same sample rate and number of blocks per syncframe. Therefore the canonical short multi-dependent writer uses one shared `3+3`, `2+2+2`, or `1x6` partition for every I0/Dn component and interleaves `I0,D0..Dn` per programme interval.
- Each canonical interval represents six audio blocks / 1,536 samples. Timestamps and source ranges advance once per interval; component ordering does not duplicate PCM time.
- TS 103 420 clause 8.2 places OAMD/JOC EMDF in the final dependent when dependents exist. The final dependent owns EMDF in both six-block and short grouped raw forms.
- TS 103 420 Table 47/48 defines idx0..idx4. Its LFE note says LFE bypasses JOC processing, so the resolver keeps LFE ownership outside the full-band matrix and validates one programme-level final owner.
- TS 103 420 Annex E is a separate CMAF rule set: one I0 plus optional D0, six blocks, and CMAF-specific sample grouping. Raw short or D1+ support is never inferred into CMAF.
- The legacy AC-3 I0 uses its fixed AC-3 frame semantics and does not participate in the E-AC-3 `numblkscod` short partition axis; legacy-core + short is `NOT_APPLICABLE`.
- Mixed partitions such as `1+2+3`, `3+2+1`, and `2+1+1+2` remain `PUBLIC_AMBIGUOUS`. Public syntax describes per-syncframe block counts but does not provide a closed JOC programme ownership convention for heterogeneous component groupings.

## Capability classifications

The semantic verdict is independent of decoder interoperability:

| Verdict | Meaning in this closure |
|---|---|
| `SUPPORTED_PASS` | Public composition, canonical ownership, capacity, and a generalized JOCForge writer plan resolve. Representative forms are validated separately. |
| `SPEC_LEGAL_NOT_IMPLEMENTED` | Publicly expressible, but the selected carriage/signaling variant has no validated JOCForge writer path. |
| `REJECTED_CAPACITY` | The requested topology cannot fit the selected bitrate allocation. |
| `SEMANTIC_CEILING` | Raw D0..D7 syntax exists, but the selected profile has no additional non-duplicated canonical full-band ownership slot. |
| `PUBLIC_AMBIGUOUS` | Public grouping or ownership semantics are not closed; no guess is emitted. |
| `NOT_APPLICABLE` | The axes do not compose, for example CMAF short or legacy-core short. |
| `INVALID` | Request fields violate a direct type, range, or ownership invariant. |
| `RESERVED` | Reserved profile/configuration values; idx5..idx7 are never emitted. |

FFmpeg status is reported separately as `PASS`, `PARTIAL`, `UNSUPPORTED_DECODER_FEATURE`, or `FAIL_STREAM_ERROR`. In particular, raw D1+ may be normatively supported while stock FFmpeg reports an unsupported decoder feature.

## Closed composition families

| Family | Closed result |
|---|---|
| Raw ETSI I0+D0 | idx0..idx4; strict or deployed EMDF; six-block and canonical short partitions; absent or independent LFE. |
| Raw ETSI multi-dependent | D0..D4 for idx0/idx3 and D0..D5 for idx1/idx2/idx4; six-block and canonical short partitions; final-dependent EMDF; absent, independent, dependent supplement, or dependent replacement LFE where the ownership plan is valid. |
| Raw deployed signaling | Signaling remains independent from raw ETSI carriage. `codecdatae=0` is not used to force I0 skip-field carriage. |
| I0 skip-field | idx0, six-block I0, strict or deployed EMDF, no dependent topology; the deployed preset selects the deployed variant by default. |
| Legacy core | strict EMDF, one E-AC-3 D0, six-block only; idx0..idx4 at 1280 kbps and the validated idx1 lower-rate cells. |
| CMAF | strict, six-block, I0+D0, idx0..idx4, no LFE; other raw dimensions remain separate. |

Dependent LFE supplement and replacement both use one LFE-bearing dependent. Replacement also serializes the independent predecessor LFE because that is the public replacement model; the final decoded programme owner is the dependent, and LFE never becomes a JOC matrix column.

For short replacement-LFE representatives, the source-causality report is scoped to every serialized source-owned field: the established independent-LFE short-frame primitive has no independent I0 full-band mantissa source field, so that sub-scope is recorded as not applicable rather than reported as a false pass.

## Validation surfaces

- `validate_ownership_plan` checks sequential IDs, map cardinality, full-band ownership, LFE policy, semantic ceilings, and final JOC ownership.
- `validate_short_multi_dependent_access_unit` independently checks CRC2, component interleaving, shared block counts, exact timing, LFE declarations, and final-dependent EMDF placement.
- `package_source_derived_short_block_access_unit_with_plan` writes source-derived full-band and LFE fields for all dependents in the resolved short plan.
- `composition-matrix` generates the machine-readable lattice at `artifacts/composition-capability-matrix.csv` and `artifacts/composition-capability-matrix.json`.
- `conformance-short-multi-dependent` generates reproducible source-derived representative streams and prints the resolved plan, including profile, carriage, EMDF, partition, dependents, LFE ownership, bitrate, and JOC owner.

The frozen OpenJOC validator resolved from `validation/openjoc-validator.json` is authoritative for inspect/render acceptance. The current source-built OpenJOC Inspector JSON is retained as a diagnostic surface; its source revision is recorded in `artifacts/orthogonal-closure/validation.json` and does not replace the frozen acceptance authority.

Heavyweight OpenJOC inspect/render, FFmpeg decode, source causality, finite PCM, continuity, and deterministic repeat checks are targeted at canonical representatives, boundary rates, pairwise interactions, and the maximum-complexity legal raw stream rather than every matrix row.

The closure script emits both the maximum semantic topology monster (`idx4`, D0..D5, `3+3`, strict, no LFE) and the maximum validated LFE-bearing variant (`idx4`, D0..D4, dependent supplement). The D0..D5 dependent-LFE short cell remains separately classified by the resolver and is not substituted into the no-LFE maximum.

## Remaining intentional closures

- Heterogeneous component partitions remain `PUBLIC_AMBIGUOUS`.
- CMAF short-block and CMAF D1+ remain `NOT_APPLICABLE` under Annex E.
- Legacy-core short-block remains `NOT_APPLICABLE`.
- I0 skip-field LFE and legacy-core LFE remain `SPEC_LEGAL_NOT_IMPLEMENTED` until an independently validated writer path exists.
- D6/D7 remain `SEMANTIC_CEILING` for the canonical JOC ownership graph, despite being legal raw E-AC-3 dependent IDs.
