publication commit `aa6ad11be84cd726573780b48b0db90b6f1c3446`.

The counts sum to 140,400. Within this modeled public ETSI E-AC-3 JOC space,
every composition classified as publicly unambiguous, semantically meaningful,
applicable, and capacity-viable has an implemented encoding path. This claim is
limited to the modeled space; it is not a claim about every imaginable Dolby
Atmos stream, proprietary encoder mode, decoder, patent, or certification.

## Authoritative boundary

The authoritative generator is
[`scripts/generate-joc-capability-matrix.ps1`](../scripts/generate-joc-capability-matrix.ps1),
which delegates classification to the Rust `CompositionRequest` /
`CompositionResolver` and `composition_capability_matrix()` path. The resolver
is the only semantic classifier. The generated matrix is also regenerated by
the census runner before selecting positive probes.

The public specification boundary is:

- ETSI TS 103 420 V1.2.1 for public JOC profile, EMDF and ownership semantics;
- ETSI TS 102 366 V1.4.1 for public E-AC-3 syncframe, block and substream
  structure; and
- the project-owned `profile_spec` and composition contracts that map those
  public rules into the modeled capability dimensions.

`SUPPORTED_PASS` is an implementation classification, not a claim of
perceptual parity or interoperability with every external product.

## Zero-gap invariant

`SPEC_LEGAL_NOT_IMPLEMENTED = 0` is an acceptance invariant for this modeled
space. The existing composition-matrix generation and census runner both fail
closed if a regenerated matrix contains a nonzero value. This document records
the invariant; it does not add a duplicate acceptance mechanism.

## Freeze semantics

After this milestone, existing public capability classifications should not
change casually. A future classification change requires at least one of:

- newly discovered public-spec evidence;
- a confirmed correctness bug;
- a new public specification edition; or
- an intentionally added capability dimension with an updated matrix contract.

Convenience, external decoder behavior, metadata labels, or a desire to improve
headline counts are not reasons to churn the frozen classifications. Future
changes should update the counts, evidence, and release notes together.

## Relationship to interoperability evidence

The 20-stream interoperability census is a version-scoped sample from the
`SUPPORTED_PASS` set. Its OpenJOC/FFmpeg/MediaInfo observations do not redefine
the matrix, and FFmpeg or MediaInfo behavior is not a legality authority. See
[`interop-census.md`](interop-census.md) for the detailed corpus and
[`joc-capability-matrix.md`](joc-capability-matrix.md) for the human-readable
matrix summary.
