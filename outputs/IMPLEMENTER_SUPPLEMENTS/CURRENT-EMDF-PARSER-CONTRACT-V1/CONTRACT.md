# Current protected EMDF parser: selected local contract

Scope: the current F13 published container, not a general EMDF decoder and not a recovered native ABI. `AncillaryPayload::validated_at_block` is the name of a frozen model helper/specification concept, not a delivered or presumed Rust API. Implement the behavior through an actual local interface. Native outgoing BSI uses a separate configuration-count source; ID14-to-native-BSI identity/generation remains UNBOUND.

## Container and field parsing

Use a bounds-checked MSB-first reader with a declared bit cursor. Require carrier_block to be an integer 0..5 (selected 2) and the entire supplied EMDF to be <=511 bytes. Require four header bytes: sync 0x58 0x38 followed by unsigned big-endian U16 body length. Require checked `4+body_length == supplied length` (an outer parser returning consumed bytes alone is insufficient); reject truncation, trailing bytes, overflow and extra container bytes. The body starts with version U2=0 and key_id U3=0 in this selected profile. Read 5-bit payload IDs until ID0; selected four-body production order is 11,14,2,1. For this production route reject wrong order, missing/duplicate body IDs or unbound body; parser-only ID14 absence is a separate primitive case. Do not interpret key_id 0 as a secret/key request.

Each payload has the conditional F13.3 config, varuint length, then exactly that many octets read from the current bit cursor. Octets need not start on a byte boundary. Varuint groups consist of w data bits followed by one continuation bit, most significant group first: initialize v=first data; for each continuation, set v=(v+1)*2^w+next data using checked arithmetic. Maximum groups: payload length w=8,m=2; duration w=11,m=2; group ID w=2,m=8. Reject truncation, overflow, nontermination or too many groups. This is not LEB128.

For every payload config, read sample-offset-presence; if present consume U11 and require extension bit0. Read duration-presence and optional varuint; group-ID-presence and optional varuint; codec-data-presence and, if set, reserved U8=0; discard-unknown. Only when discard=false: if sample offset absent, read aligned flag and if aligned read create/remove flags; if sample offset present or aligned=true, read priority U5 and processing-allowed U2. Fields not present must remain absent rather than silently becoming zero. Parse ID1/ID2 using their own approved producer configs; selected mode restrictions below apply specifically to IDs11/14.

For ID11 and ID14 both modes require sample offset and duration absent, group present with value0, discard=false. `deployed_compat` requires codec_data=false for both, ID11 aligned=false with duplicate/priority/processing fields absent, ID14 aligned=true with create/remove=false and priority/processing=0. `etsi_emdf` requires codec_data=true plus reserved U8=0, aligned=true and create/remove=false and priority/processing=0 for both. Bind the actual mode to the fixed programme plan; an unknown mode or mismatch fails. This narrow mode table does not assert general ETSI or commercial player compatibility.

After ID0 read primary length code U2=2, secondary U2=1 and respectively 32 and 8 checksum bits. Record their exact bit positions. After checksum fields allow at most seven remaining padding bits, all zero. Reject bad codes, truncated bits, nonzero/excess padding. F13.1–.3 and .9 specify framing; F14K.1–.4 specifies protection. Generic profile checks in the frozen helper do not, by themselves, establish CRC verification.

## F14K protection verification

Preserve the supplied protected container. On a copy set exactly the 32 primary and 8 secondary checksum *bits* to zero, preserving all adjacent bits, payloads, fields, body length and zero padding. The message is the copy's body bytes starting at offset4, including zeroed slots and padding. CRC32/ISO-HDLC starts `0xffffffff`, XORs each byte into low 8 bits, iterates 8 reflected steps with polynomial `0xedb88320`, then XORs `0xffffffff`. Compare the unsigned result with the primary field encoded big-endian in the 32 bit positions. CRC8/SMBUS starts0, XORs each of those four primary octets in network order, iterates 8 MSB-first steps using polynomial 0x07, no reflection or final XOR; compare secondary bits. Known checks for ASCII `123456789`: CRC32 `cbf43926`, CRC8 `f4`. Reject any mismatch and never authenticate by presence alone. Do not zero neighboring bits when protection is unaligned. This checksum is not secret authentication; E-AC-3 frame CRC16 is a separate later F12/F14 operation.

## Semantic ID11 and ID14

Parse selected ID11 from its exact bounded payload using F05O.2–.6 and F05T.3–.4: global version U2=0, row count (`count-1` U5, escape31 then additional U7), shortcut=1, leading LFE and protected-sections=0; selected has leading LFE plus 15 object slots, hence 16 rows. Section count U4 is 1 or 2. Each section has kind U4, escaped payload-byte-length-minus-one using w4 and up to four continuation groups, then an independently bounded bit payload (it need not be outer-byte-aligned), control bit0, syntax and zero padding. Require one rowdata kind1, at most one trim kind2, no duplicates/unknown kinds/truncated data/nonzero control/excess or nonzero tail. Decode timing and object rows according to F05O.4–.6, including conditional muted rows, gain reuse, supported spread/extension/width/ancillary and exact row count; trim follows F05T.3–.4. Reject unsupported or reserved branches rather than fabricating values. The parser must obtain 16 actual OAMD object classes/slots, not infer them from the other payload.

For ID14, F05Q.3–.6 specifies header downmix U3, count-minus-one U6, extension U3, clip U8 and sequence U10. Require selected downmix3 (five non-LFE carriers), count15, extension0 and correct body boundaries. Parse all 15 object present flags and their descriptors, then all corresponding object/point/channel/band coded data with the exact six `parameters/joc-huffman-v1.json` codebooks; reject invalid/truncated Huffman code, channel index outside 0..4, unsupported selected profile or unexplained/nonzero padding. See F05QH.3–.4 for table validity and errors; do not treat a valid 30-bit header as a valid full body. Selected F05JL supplies all 15 present slots, capacity <=372 bytes and sequence from the original popped writer; producer receipt may be cross-checked but cannot replace parsing.

When ID14 present, full validated local profile requires exactly one ID11 and ID14, selected matching group/mode, five channels, 15 JOC objects and 16 OAMD slots. Derive `complexity=U8(object_count+1)=16` from that parsed current container, checked against the popped ID14 producer receipt when available. Supply the very same owned protected bytes and complexity to the F12 source with correct source/AU/queue lineage. In the separately exposed generic primitive, no ID14 yields no complexity, not a stale value. Source0/1 publication gate must skip container/complexity and use ABSENT; source s>=2 publishes AU s-2 and receives ID14 writer s-1. F13JO section1 and F12-COMPLEXITY-ADDITIONAL-BSI-LINEAGE-V1 define the local model relation; they do not prove native source identity.

## Findings and evidence limitations

F13, F05O/F05T and F05Q/F05QH are producer-wire specifications and define the selected inverse obligations above, but this audit has not demonstrated that the exact selected generated ID11 trim body is accepted by the previously frozen OpenJOC observed-vendor-compatible parser. In particular its reserved-warp3 compatibility branch may retain an opaque element; do not assert full structural semantic equivalence or strict ETSI conformance from an opaque acceptance. The older native ID11-boundary selected seed accepts extra bytes at its nested boundary, whereas the local selected parser here requires its own bounded payload/full-consumption rule; neither observation establishes a universal native rejection. Complete selected OAMD+ID14 wrapper model-helper success remains NOT_RUN. Additional real generated-payload testing is required before reporting complete semantic interoperability.

Synthetic independent bit-framing prototype exercised both selected mode configs, F14K checksum placement (including unaligned fields), full outer length and corruption rejection, with regular Python and `-O`; payload octets were artificial and body semantics were NOT_RUN. It does not independently validate entire parser, production composition, native code or ADM. The companion INPUT-ONLY file specifies cases; it contains no copied expected bytes. Approved test vectors remain input/expected evidence, not a production lookup table.
