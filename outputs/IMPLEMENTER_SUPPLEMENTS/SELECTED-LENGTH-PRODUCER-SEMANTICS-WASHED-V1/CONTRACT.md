# Selected length producer evidence

## Scope

This is a bounded native-evidence mapping for one authorized ADM BWF and selected profile 10. It is not a codec implementation rule, full input policy, or JOCForge runtime result.

## Run-99 upstream producer

The run-99 capture observed 4,249 parent invocations and 4,247 calls to the selected producer. All calls had bounded scalar reads and were joined to the selected cold owner/profile. Returned values matched the reported static sum/tail replay for 4,247/4,247 calls.

The captured threshold, candidate, and pretrim fields were bounded U32 reads. The intake does not establish their units, semantic record schema, full arithmetic formula, or consumer units. The number 4,247 is the call count; it does not mean each producer returned 4,247.

## Run-100 downstream body length and reservation

In a separate run-100 capture, the selected body-length/count field joined to codec-record, planned, serialized, refill, and U16 body-length-prefix values for 4,247/4,247 same-parent calls. These downstream values represent body bytes in this observed chain; lengths ranged from 232 to 375 bytes.

For block 2, the U16 wire reservation, body-region reservation, and 9-bit writer operand matched body length plus 4 in all 4,247 observations. The writer advanced 9 bits. This establishes the observed numeric relation. It does not establish what the extra 4 represents or the behavior for values outside the observed range.

The run-99 and run-100 summaries do not provide a common DLL image identity. Do not join them as one execution. Run-100 did not observe target operands 507, 508, 511, or 512. The 512 overflow outcome is unknown. Parent invocation to ADM sample position remains `UNBOUND`.

## Evidence boundary

The underlying captures report no PCM/audio payload read or persistence. Model codec execution and targeted boundary fixtures are `NOT_RUN`. The run-99 upstream field units and complete producer formula remain unresolved. This package does not close the input-to-sample-position mapping or prove JOCForge output.
