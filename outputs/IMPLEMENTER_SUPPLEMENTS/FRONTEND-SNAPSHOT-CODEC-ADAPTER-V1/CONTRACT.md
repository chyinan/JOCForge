# Snapshot generations and accepted codec candidate

For Wash review. These are local typed bindings, not native transaction claims. Approved `FRONTEND-NORMAL-CONTROL-SNAPSHOT-BINDING-V1` requires a normal proposal to bind programme/attempt/prepared input, physical route, generation g, actual sampler-before state and query; it retains complete values and commits its after state and snapshot only with the parent. It does not require the previous snapshot's producer-before digest to equal the current callback's before-state digest.

For sequential successful g0→g1: the prior immutable snapshot retains its g0 origin, g0 producer-before identity and values. Current g1 preparation uses the actual committed g0 after state as g1 before and binds its own before digest. Validate actual g0 after-state identity against the actual g1 before-state identity and parent programme/attempt/prepared identity and callback clocks. The two producer-before digests may differ, as may the snapshot values. Require neither equality nor inequality: an unchanged state may have equal digests. Compare identities in their proper domains; hash equality alone does not establish ownership. g1 consumes actual carried sampler state, not reconstruction from prior row values. On late failure discard g1 proposal, retaining committed g0 state/snapshot; drain holds the last normal snapshot while downstream state advances.

The approved codec source contract freezes actual same-source analysis/numeric plan, BSI and payload before trials. Test q16 first then the approved midpoint search; each candidate has fresh BAP/quantizer/groupers/bitwriter scratch, and only legal candidate infeasibility is retryable. A minimal local accepted-candidate typed proposal should bind programme/attempt/transaction/source, actual immutable shared-analysis and numeric-plan receipts, metadata or ABSENT selection, accepted q and candidate/trial identity, exact owned frame bytes and length, frame digest and actual integrity/CRC result, plus staged codec after-state and owner receipt. Acceptance must come from the actual successful search and checks, never a supplied q, hash-only frame, fixture lookup or a fabricated receipt. Candidate failure cannot advance persistent state; no accepted candidate or preflight/provider failure is fatal.

F15 consumes the accepted proposal under the private validated plan/provider/destination binding; it does not rerun DSP or trials. Source0/1 validate scratch frames but suppress append; for s>=2 validate AU=s-2, frame size4096, CRC and expected staging offset, then append/readback/fsync before the one parent root swap. IO failure abandons and retires the attempt; final rename followed by parent-fsync failure can leave a visible path without DONE. No production constructor or real DSP/IO was executed here. Exact receipt field encodings belong to their existing owning schemas; the above is a local minimal semantic seam, not a claim of an existing Rust API.
