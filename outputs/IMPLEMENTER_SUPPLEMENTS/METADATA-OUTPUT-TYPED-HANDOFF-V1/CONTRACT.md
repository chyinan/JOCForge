# Metadata handoff and output admission: proposed local types

Status LOCAL_MODEL_PROPOSAL_FOR_WASH. This is a concrete interface design derived from approved contracts, not an observed native ABI or a claim of existing implementation. It preserves the approved current-container parser; producer provenance supplements it and never substitutes for validation.

## ID14 body through FIFO to published F12 input

F05JL accepts one generation of approved F04C receiver/target/carrier outputs and same-generation geometry/control/config; it runs temporal, geometry, fit180, profile retry and Huffman. After complete body construction, sequence insertion, capacity/padding and body identity checks, produce an immutable, owned `Id14BodyProposal` containing: programme/attempt identity; producing transaction ID; producer generation; dispatch d>=1; writer w=d-1; original codec source w; callback zero-based d+1 and one-based d+2; sequence U10; typed selected object count U8; full body bytes and actual byte length; body SHA-256; and references to the actual successful F05JL stage/owner receipts. The count comes from the same accepted selected representation and its 15 present object slots, including inactive slots. It is not the raw ADM object count or OAMD total rows. A SHA or numerical equality verifies content but does not substitute for owning the bytes or binding the producer receipt and generation.

On the emitted ID14 header independently read the first 30 bits MSB-first: downmix_index U3 at bits 0..2; object_count_minus_one U6 at bits 3..8; extension_config U3 at bits 9..11; clip_gain_index U8 at bits 12..19; sequence_count U10 at bits 20..29. For selected output require downmix=3, count=decoded U6+1=15, extension=0, clip in 128..255, and decoded sequence equal to the successful same-dispatch sequence. Reject truncated header, malformed fields, disagreement with the typed producer count/sequence or receipt, invalid selected profile, or body over selected 372-byte capacity. These header checks alone do not validate the complete body, Huffman data, padding, OAMD or EMDF protection. The approved whole-container parser and all its applicable checks must still succeed.

At SourceTransaction s, require d=s+1 and w=s, current transaction/programme/attempt identity and same generation for all four ready input bodies. F13 stages ID11/ID1/ID2/ID14 push then pop in [11,1,2,14]. Store the actual owned body together with its producer provenance in each occupied slot. A later pop preserves its original producer transaction and writer identity, and records a distinct current consumer transaction/source; do not demand those two transaction IDs match. A queue buffer ID is only storage identity. Current consumer source s>=2 must use ID14 writer s-1 (producing dispatch s), plus ordinary writers s-2; the AU index is s-2. Source1 consumes/suppresses ID14 writer0; it must not carry over to source2. Source0/1 return ABSENT_PUBLISHED_PAYLOAD_V1 without building or parsing an EMDF.

For source s>=2, serialize the actual popped bodies once in [11,14,2,1] using fixed plan carriage and F14K protection, forming an immutable `PublishedPayload` with current programme/attempt/consumer transaction/source/AU, original popped writer identities, carrier block, carriage, exact protected container bytes, byte length and digest, and queue/protection receipts. Ownership and transaction/queue bindings establish provenance; hash alone does not. `AncillaryPayload::validated_at_block` must consume this exact container and carrier block, require total length <=511, full parser consumption and selected JOC/OAMD profile plus applicable protection validation. If ID14 exists it requires ID11, downmix3, five carriers, ID14 object_count15 and OAMD slots16, and returns complexity U8(15+1)=16. Independently compare the parser result with the popped ID14 producer count and header; disagreement fails the source. If ID14 is absent, the approved parser returns no complexity and F12 writes addbsie=0; whether a particular four-producer selected composition can generate that case depends on its upstream contract, so absence is not invented as a normal selected live output. Do not forward complexity from the current producer when the queued producer is earlier. F12 uses the same protected container object/result to write the source's frame and BSI bits 105..112; no separate reserialization or previous-source fallback.

Before root commit, all stage outputs, same-source queue receipt, container/complexity validation, F12 frame/integrity and any required durable append must succeed. A producer/header/queue/parser/protection/generation/append failure discards staged owners and produces no published source result; fatal handling follows the parent contract. Source0/1 still advance their staged owners on success. Existing legacy local leaf APIs are not authority to commit early. Native configuration-byte-to-ID14 source/generation join remains UNBOUND and does not block this explicitly model-owned pipeline.

## Minimum private validated plan

Proposed private typed fields, preserving actual handles rather than only hashes:

* `PreparedInputIdentity`: programme identity, resource identity/SHA, configuration identity/SHA and positive N; reference to the validated prepared input.
* `ResolvedProfile`: the actual six-dimensional validated profile object and its selected codec profile identity, with exact sample rate 48000, bit rate 1024000, 5.1/acmod7, uncoupled/non-SPX route as required by its resolver; carriage is a separately typed deployed_compat/etsi_emdf selection. The six actual source field names remain unspecified by the audited F15 material: do not invent a six-field list or treat a profile string/frame size as complete validation.
* `ProviderAdmissionSet`: approved package and F15 manifest identities, actual stage/provider validator-owned immutable handles or receipts for selected codec, JOC, F13 and F14 plus other mandatory dependencies selected by their approved manifests; each reference must bind its validation identity and profile/carriage where applicable. This is an aggregate of actual validator outputs, not a fabricated all-purpose receipt or future per-source receipt. The exhaustive concrete receipt field schemas and extra dependency enumeration must come from their owning approved interfaces; absence or failed validation means no plan.
* `OutputPolicy`: privately derived canonical provider bytes and SHA from the approved F15 projection, matched to the selected codec profile, manifest identity and carriage. The caller cannot select the provider independently.
* `ProgrammeOutputBinding`: actual plan reference, same programme and attempt, typed U64 AttemptId, distinct opaque parent-owned staging owner, and validated destination capability. Attempt decimal serialization is derived internally. Attempt-only equality or a caller-supplied hash is insufficient.

Runtime `SharedAnalysisReceipt`, `NumericPlanReceipt`, F05JL, FourQueueReceipt, F12/integrity and durable output receipts arise from each actual execution and are checked at their source/commit boundary; they cannot be fabricated when constructing a plan before the work occurs. Each staged owner receipt binds owner, before/after generation and hash, actual after-state reference, changed, commit_count and transaction ID under the existing global contract. MeasurementReceipt is available after the completed meter prepass; failure leaves no such receipt and retires the attempt. Production eligibility requires actual successful validation and relevant runtime receipts, not synthetic fixture evidence. This minimal design leaves actual construction and execution NOT_RUN.

## Destination admission: minimal local policy

Treat destination as a parent-validated capability, not an arbitrary path embedded in provider bytes. Before staging, require a nonempty supported local file destination and a usable existing parent directory; reject malformed path, directory-as-file, same source and final destination, conflicting programme/attempt/staging binding and an already existing final destination. Reserve a fresh attempt-private staging namespace and prevent collision with another attempt. Keep final path unpublished until successful final checks. Open/create and later operations must be checked again by the shell, not trusted solely from a prior existence check; fail closed if safe exclusive creation or no-clobber final exposure cannot be supported. These concrete checks are a proposed local policy, not a vendor rule or universal cross-platform atomicity guarantee. A destination check alone cannot prove fsync, atomicity, power-loss recovery or authorization. Errors before IO leave state unchanged; errors after partial physical IO retire and abandon the attempt, never expose it as successful or continue it.

## Evidence and limits

The approved F05Q.3 wire header layout and F05JL.5/6 selected profile/clock supply the typed cross-check. F13JO supplies the full validated-container complexity rule; F13/F15/GTC supply FIFO, published gate and staged ownership. The attached synthetic header/clock prototype exercised sequence 0/1/1023 and a truncated input under regular Python and `-O`; it did not execute the full parser, a real producer, native code, F12, file publication or ADM. Existing package vectors are not production identity or audio evidence. Real ADM encoding, output structure and player spatial verification remain NOT_RUN.
