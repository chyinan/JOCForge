# F15 provider roles and destination admission

## Confirmed plan roles

The approved F15 binding has four top-level roles: codec/F12, JOC/F05, F13 metadata, and F14 public integrity. The 25-entry provider manifest is a mixed dependency inventory. It contains specifications, runtime parameter assets, cross-module indexes, fixtures/reviews, and context. It is not 25 loaded provider receipts.

Each role's owning validator must validate actual loaded or compiled values against the same resolved profile and carriage. Hashes identify source assets; they do not prove that values are loaded, installed, or valid. F06/F07/F08 source-stage values remain owned by their own validators and are not collapsed into four plan receipts.

At plan admission, only actual role admission values may be bound. Source, dispatch, frame, measurement, integrity, and durable-publication receipts arise later when their owners execute. A fixture marked `production_allowed=false`, manifest entry, or expected digest cannot stand in for those runtime receipts.

The inspected F15 contract does not define one unified provider-admission receipt schema. The role-specific immutable-handle aggregation in the reverse package is a local design proposal, not an existing Rust API or a native DEE fact. This supplement does not approve new public fields or constructors.

## Destination boundary

The approved contract requires parent validation of the chosen destination/path, binding to programme and attempt, a distinct opaque staging owner, and the existing no-overwrite rule. The I/O shell performs real exclusive staging/open, append, readback, durable flush, and final exposure; receipts follow those operations.

The reviewed contract does not identify the exact destination-capability producer or result schema. The proposed private parent capability is a local design option only. It adds no platform-wide symlink/race guarantee and is not a durable receipt. Runtime destination validation, plan construction, OutputOwner construction, filesystem durability, and final exposure remain `NOT_RUN`.
