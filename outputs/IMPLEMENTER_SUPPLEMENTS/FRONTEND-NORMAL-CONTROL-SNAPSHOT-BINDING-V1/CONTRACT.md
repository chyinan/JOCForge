# Callback-owned normal frontend control snapshots

This is a minimal binding of current approved F01E.7–.10, its selected constructor and the approved bed/object source-flags adapter. It does not require a native capture or a vendor receipt ABI. It defines how the existing event/control owner is invoked by the F03W parent; it does not add another sampler state, generic framework or backend stage.

## Inputs and cold binding

The parent supplies owned Prepared graph/config/events/physical routes and matching DBMD identity after the existing parsers/validators. N comes from the actual prepared source descriptor; the constructor's example programme count is not a new song-independent constant. Use the selected provider's cold fields: callback/normal counts0,28 object nested entries with previous absent/zero and no event cache, nullable physical/DBMD binding and no snapshots. Immutable normalized config belongs to the actual programme.

Resolve bed pack references by exact channel_format_id and physical host. Object ordinal is an identity index into28 nested records, not host=ordinal+10. Bed/object hosts form a disjoint complete0..37 union; exactly one bed_id3/semantic LFE is removed, wherever its host is. Derive regular37_host_order by physical ascending order. Binding may be prepared once, but installation must be a complete staged owner proposal, never a partly published collection of per-row writes.

## Normal invocation and sampler

For NORMAL callback g, require the same programme/attempt/prepared identity and next callback clock. query=g*1536<N. Last normal actual=N-g*1536 may be shorter than1536; raw padding does not change event/control processing. The event itself still has start/rtime0. Period512/three slots specify numeric sampler steps; do not look up a new event at gH+512/+1024 beyond N on a padded last frame.

Preflight the entire graph, binding,28 events and input state before publishing anything. Build the object processing view in ascending physical-host order, while each object's one sampler state remains addressed by its object ordinal. Thus a permuted ordinal/host mapping must not permute identities or read a neighboring object's previous XYZ.

Use the complete F01E.8 coordinate/default/sentinel/writer-clamp and spread rules. First valid state initializes previous from current writer XYZ. Every normal call then executes slot1 followed by slot2 from the actual owned previous value, with two separate R32 products and one R32 sum per axis and slot. Carry the resulting XYZ in that object's proposed nested state. Do not use the old worker's once-before-loop first-record helper as a normal implementation, skip updates for constant events, or reconstruct previous from the event each callback.

Produce each Object13 row by F01E.9 using current sampled XYZ and uniform_width. DBMD track fields remain attached to the matched physical identity and are not inserted into control slots11/12. Full parser/event/profile acceptance stays the existing F01E contract, not a weaker subset in the small metadata verifier.

## Metadata views and snapshot storage

PrimaryMetadataControlRows is the admitted identity/control view, not a static replacement for sampler output. Its bed entry keeps exactly six defined words[0,0,3,2,1,bed_id] and raw bytes24..51 UNPRODUCED. Its object entry carries the actual current13 words. The normal producer pairs that view with the callback-owned values/receipt; cached metadata labels alone cannot satisfy sampling.

Use tagged Bed6/Object13 immutable runtime views. For SourceFlags, Bed explicitly supplies mute0 and finite positive-zero width through the approved adapter, without reading any raw tail or padding. Object supplies mute from current word0 and sampled uniform_width from word9. Feature component/diffuse uses its separately approved selected view, not authored audio diffuse copied into another domain.

The existing constructor explicitly names rectangular owned snapshot storage U32[38][13] and U32[37][13]. If that current canonical storage is materialized, a bed's first six words are the defined prefix and its remaining slots are local unconsumed zero padding only. This is clean internal carrier representation, not a produced thirteen-word raw bed record. The existing runtime bed/object binding determines which slots are semantic; no consumer gains permission to read the padding. Runtime consumers do not need another13-word bed carrier to obtain RegularControl. There is no new authored bed-width rule and no upgrade of raw-tail evidence.

Every object has a complete current row. control38 is physical host order; regular37 is a projection through regular37_host_order. Store the entire successful snapshot atomically, not one row at a time. Source geometry receives those same sampled XYZ/attributes/current width references with the current runtime route; static programme basis and layout do not supply object updates.

## Generation, parent commit, failure and reset

Successful proposal values have generationg and normal sampling origing. Their receipt binds actual immutable values plus programme/attempt, prepared input, physical mapping, sampler-before and query; a digest or matching row count cannot replace the arrays. next callback_index becomesg+1 only as part of successful commit. A downstreamg+1 packet domain needs its explicit adapter; it must not rewrite the source producer origin.

The leaf returns a complete private proposal. F03W consumes it once for render/flags/features and the rest of the enclosing callback. Only the existing parent transaction commits the event/control after state and snapshots together with its other owners. A failure on the last object or any later stage exposes no partial control rows, advances no committed sampler/counter, and leaves prior snapshots/state unchanged. A computed leaf proposal is not a second commit. Use existing I03 failure/retirement semantics; do not retry by borrowing old controls or silently reset individual objects.

Meter drain behavior remains the already approved hold supplement. It retains the last normal source snapshot/provenance while downstream processing advances. This binding neither changes its three-zero-input schedule nor imports main four-cached audio. Reset drops event cache, previous XYZ/presence, binding/DBMD, snapshots and counters and reconstructs fresh selected owners for the new programme/attempt.

## Verification scope

The self-owned N1537 fixture has ten beds interleaved with28 objects, semantic LFEhost12, reordered pack joins and reverse ordinal-to-host object mapping. The replay executes two normal proposals including the one-sample last frame, cold copy and per-call two-slot updates. It checks explicit carried-state dependence, sentinel and signed-zero preprocessing, late preflight failure, generation/owner mismatch, private parent discard and mutable-output isolation.

The explicit alternate previous-XYZ case is a supplied-before-state transition fixture, not a claim a constant-event programme reaches that state. Checks do not execute the full XML/DBMD parser, F03W DSP parent, native DEE or actual PCM. Proposal/discard evidence is the clean metadata model, not a recovered native transaction. Existing approved rules supply all selected numerical inputs; real Rust integration must invoke these producers rather than use the verifier or its recipes as runtime inputs.
