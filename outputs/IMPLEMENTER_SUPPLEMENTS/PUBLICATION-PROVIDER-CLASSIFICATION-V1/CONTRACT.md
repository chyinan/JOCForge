# Keyless publication provider classification

The 25 entries of `parameters/keyless-publication-providers-v1.json` are a package dependency inventory, not 25 runtime receipts. Its raw SHA-256 is `a2cf06839d3da81d14240ccd6526eebc0b878721d48a03fd0d0813f26961f6ce`. All 25 current file byte counts and hashes were independently checked. Classification is by actual role, not merely a file's directory; local implementation may compile approved nonsecret constants rather than load JSON at runtime, provided it validates the actual values and identity through an equivalent trusted mechanism.

## Minimum semantic handles and validation

The trusted plan aggregates actual validated typed provider handles/references, rather than hashes alone. Concrete type names are LOCAL_MODEL, not a claim about a current Rust API. At admission, validate the selected profile and carriage against actual prepared input and validate each selected dependency's identity, schema, shape, ranges and relationships as prescribed by its owning specification. Store actual immutable data or references plus source identity. Missing, malformed, wrong-profile or substituted data rejects admission; a manifest hash only authenticates a list and cannot prove a referenced numerical asset was loaded or validated.

## Execution receipt timing

Provider admission checks occur before creating an authoritative private plan; the result binds actual validated providers and prepared input. The independent programme MeasurementReceipt is produced only after completed meter prepass. Each callback/source then produces real owner/state-bound receipts as work executes: shared analysis once, F06/DRC and numeric plan from it, JOC body and F13 queue/container from their actual producers, F12 winning candidate/frame, F14K integrity, and for published AUs an actual durable append receipt. Bind programme, attempt, source, transaction, owner/generation and actual owned values according to each owner contract; do not pre-mint those receipts from the provider inventory. Source0/1 have no append receipt. Parent commits after the applicable gates; final exposure receipt occurs only after actual terminal/durable finalization. Any missing actual provider or required runtime receipt rejects or fails at its proper boundary.

The independent audit verified bytes/hashes of 25 listed files and three additional approved JOC/OAMD assets against the main package manifest. It did not execute provider loaders, actual value-domain validators, DSP, publication or ADM playback: those are NOT_RUN. Selected runtime receipt/handle design remains a proposed local seam for Wash review, with no native token or vendor authentication dependency.
