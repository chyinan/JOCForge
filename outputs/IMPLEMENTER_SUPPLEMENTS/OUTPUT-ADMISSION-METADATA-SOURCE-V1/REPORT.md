# Selected output admission and metadata source audit

This is a source audit of existing approved/Wash material, for Wash review. It defines no new native ABI and reports no implementation or production execution. The implementation repository was not read.

## F15 plan and provider

PreparedJobInput identifies the programme, resource SHA, config SHA and positive sample count N; it is not output authority. The trusted programme parent forms a private ValidatedEncodingPlan only after binding that same prepared input to the exact supported six-dimensional EncodingProfile, the selected carriage, approved package/F15 dependency manifest and actual validated selected codec/JOC/F13/F14 provider/stage receipts. A parent-owned construction path then takes the plan, typed U64 AttemptId, a distinct opaque staging owner and destination, and internally derives OutputProvider. OutputConfiguration/OutputOwner carries the derived SHA and must compare it with the plan projection before staging. The selected policy is a local Wash decision, not a recovered vendor provider.

The selected projection object has exactly these fields: schema `output-owner-provider.v1`; profile_id `selected-keyless-output-policy.v1`; encoding_profile_id `eac3-joc-48k-1024k-acmod7-uncoupled-nonspx`; emdf_carriage_mode; f15_dependency_manifest_sha256 `a2cf06839d3da81d14240ccd6526eebc0b878721d48a03fd0d0813f26961f6ce`; frame_bytes 4096; suppressed_sources 2; staging_name_template `attempt-{attempt_id}.ec3.partial`; intent_name_template `attempt-{attempt_id}.finalize-intent.json`. The F15 profile ID and codec profile ID are separate namespaces; the plan binds both. Provider SHA is over canonical UTF-8 JSON with sorted keys, comma/colon separators, no extra whitespace, BOM or newline. For deployed_compat the SHA is `e5d18a8b140e768279ef0cc282aafc3495f42720030ed95522bf8ed240b221c5`; for etsi_emdf it is `d4ba533d06ddf9bda330023891919e8a233ee8a12611eec051708012034b1687`. The latter is explicit experimental carriage; omission chooses deployed_compat. A carriage change requires fresh serialization and frame trial, and is forbidden mid-programme.

Derive Q=ceil(N/1536), source count Q+2, published AU count Q, product bytes Q*4096 with checked arithmetic. These variable counts are not provider-hash inputs. Before IO reject missing/test-only plan, mismatched programme/resource/config/N, unsupported profile/carriage, mismatched manifest/typed receipts or projection hash, stale/cross-bound attempt, staging owner or destination, and count overflow. Source0/1 suppress output; the parent commits staged leaf state only after all applicable source and durable-output checks. A physical append failure retires the attempt; no continuation is implied.

Actual constructor implementation, receipt-set assembly, filesystem and end-to-end programme remain NOT_RUN in the cited decisions. Their field-level mapping is a contract, not proof an executable constructor exists. The cited contract references an existing six-dimensional EncodingProfile and validator but does not enumerate the six concrete field names or a complete OutputConfiguration/ValidatedEncodingPlan serialization schema. It does not define all individual stage receipt schemas or the exact destination validation rule; these remain to be obtained from corresponding approved interfaces, not guessed. The fixture OUTPUT-OWNER-ROOT-V1 is production_allowed=false and cannot serve as the production provider identity, sample count, authority or proof of production filesystem behavior.

## F13 publication and F12 complexity

The approved clean model permits the published EMDF produced by the F13 stage to be the same source container consumed by F12, subject to the actual composition passing the same bytes and bound source/carriage identity. A proposal alone does not establish that handoff: the inspected approved specifications define four body proposals and staged queue/serializer behavior but do not specify a complete public `MetadataSourceProposal` struct schema, nor prove an actual implementation forwards the same serialized container. Use a single owned immutable result or equivalent explicitly bound handoff; do not reconstruct it from an old container or a reference fixture.

Each source s requires successful same-writer ID11/ID1/ID2/ID14 bodies before any queue mutation. F13 pushes/pops in [11,1,2,14], serializes popped output in [11,14,2,1], and stages state. Source 0/1 use ABSENT_PUBLISHED_PAYLOAD_V1: no EMDF serialization, complexity parse or published-payload checks. At source s>=2, the freshly serialized, protected container is consumed by F12 for AU s-2. The ordinary ID11/ID2/ID1 popped writer is s-2, while ID14 popped writer is s-1; these are intentional queue delays, not four identical output generations. The proposal inputs themselves must be of the current writer generation before queue push.

The approved typed model producer `AncillaryPayload::validated_at_block` consumes the current complete validated selected EMDF and carrier block; it derives U8(joc_object_count+1) when ID14 is present and ID11/profile validation succeeds. Selected object_count 15 gives complexity 16, written in F12 additional BSI bits 105..112; carrier_block 2 is a placement input, not complexity. The model producer has no persistent state and recomputes per published source. Missing ID14 yields absence; invalid profile, missing ID11 for ID14, incomplete consumption, oversize container or invalid carrier block must fail per approved rules. Native outgoing BSI configuration byte is separately sourced; native semantic ID14 reader/owner/generation join remains UNBOUND, despite matching the model's value. A complete real OAMD+ID14 wrapper and actual F13-to-F12 typed handoff are NOT_RUN.

## Verification and next executable step

This audit independently verified all listed manifest payload hashes for four named supplements, the three F15 approved base identities, and reserialized both provider objects to reproduce their declared SHA-256 values. Source and projection checks are not product validation. The minimal next local composition is an input-only case that derives a provider from actual typed plan inputs, stages four real approved producer outputs for a single source, serializes the current container once, validates it and passes that exact result to the F12 candidate path; check source 0/1 absence, source 2 publication, carriage mismatch, failed producer and failed append independently. Full schema or unavailable producer receipts must remain explicit; no synthetic fixture is a production substitute. Real ADM encode, structural validation and supported-player spatial playback must be assessed separately in the user's requested sample/configuration range.
