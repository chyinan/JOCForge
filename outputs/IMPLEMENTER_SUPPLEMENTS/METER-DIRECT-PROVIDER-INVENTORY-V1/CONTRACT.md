# Meter production provider inventory: verified direct assets and boundaries

This is a bounded inventory, not a claim that the entire transitive independent frontend provider set has been enumerated. All seven assets in INVENTORY were independently matched to the approved main package manifest. The selected meter has independent input/frontend/component, reader controls/LFE, OAR, DV32, K/window/energy, integrated/ungated, true-peak and terminal owners. The approved `parameters/adm-installed48-providers-v1.json` is a broad upstream dependency index, not a loaded numerical provider and not proof of successful production validation. Follow its relevant F01/F03/F04/F05 identities and their owner-specific contracts for the actual input/profile. No native owner token is required for a safe approved local parent identity.

## Direct owner assets

* OAR geometry: `meter-oar-secondary8-math-v1.json`, schema `meter-oar-secondary8-mathematical-geometry.v1`. The OAR owner validates actual selected eight-slot geometry/profile, row/control shape and finite numerical inputs and obtains actual same-callback component/control and LFE rows. It is not an input PCM or zero-row fixture.
* Shared DV32: `shared-dv32-mathematical-v1.json`, schema `shared-dv32-mathematical-parameters.v1`. Validate actual six-row/32-sample/48k profile, coefficients and owned state according to DV32 spec; it is independent of main-encoder histories.
* K/filter and window: `meter-k-matrix-math-v1.json` (48 kHz two-stage matrix; the inspected asset does not declare a schema field), plus `meter-k-state-bounds-v1.json`, schema `meter-k-basic-state-and-bounds.v1`. Validate actual coefficient matrix shape/values, stage/lane bounds, positive-zero cold state and noise, then use separate F32 filter histories and energy mantissa/exponent owners; K I32 field is not the energy exponent. Apply F06W segmentation, 1024 block/960 window and rounding rules.
* Integrated/log: `meter-log-mathematical-v1.json`, schema `meter-log-mathematical-constants.v1`. Validate the consumed exact mathematical constants/R32 conversion and the integrated/ungated state and gating contract; final programme values require actual whole prepass.
* True peak: `meter-truepeak-authorized-v1.json`, schema `meter-truepeak-authorized-functional-constants.v1`. Validate actual authorized 48k coefficients, shapes and six-channel FIR state according to true-peak contract; source class is explicitly authorized compiled functional constants, not independently derived mathematical design, and excludes secrets.

Owner validation must bind actual immutable typed values and profile, not only raw file/manifest hashes. Compiled-in constants are permissible only under an equivalent trusted identity and value-validation mechanism. Resolve all other consumed parameters from the respective approved owner manifests; do not infer a complete transitive set from the seven direct entries above. Before each callback bind the actual prepared input, current programme/attempt, current committed owner state, source clock and same-generation producer outputs; each owner stages its actual next state. Meter terminal getters and MeasurementReceipt are produced only after actual successful terminal work and are checked under the parent transaction. Source fixture receipts are not substitutes.

`METER-LIFECYCLE-SEAM-V1` explicitly marks `PRODUCTION_ALLOWED=NO`, real ADM frontend/render and real filter/true peak `NOT_RUN`; its vectors/receipt verify a test seam and cannot provide production values or authorize a real prepass. Input-only V4 cold materializations likewise do not supply actual warm state, measurements or terminal hash. The independent prepass requires Q normal plus three fresh-zero raw-input drains, actual render/OAR/DV and full meter states, then terminal validation and receipt; a local owner key can bind the parent without a native pointer proof.

This delivery checked file identities only; it did not execute provider loaders or each owner's semantic validator, actual ADM, DSP, measurement, playback or production receipt. Those are NOT_RUN. The missing exhaustive transitive owner inventory/validator-specific machine schemas must be taken from approved owner packages or separately audited; this list must not be presented as an exact complete production manifest.
